**T0 ★ 接地缺失是失败的共同根源。** 失败发生(认知错误)、成败分野(验证纪律)、失败昂贵化(锁死后停止接地)、失败难检测(监视器缺规格参照)——四个层面是同一件事:信念与环境真实状态的脱节。这不是单独 finding,是把 F1/F4/F9/F6 串起来的主线,abstract 首句与 conclusion 尾句用它。

## RQ1：失败如何、何时开始，以及在多大程度上可被识别

**F1 ★ 失败主要是认知性的,不是能力性的。** 认知性触发占 **57.9%** [CI 0.55–0.61]:false_premise **30.7%** 居首、spec_neglect **14.9%**、misread_output 4.4%、ignored_signal 4.1%、premature_action 3.7%;能力性触发 **32.8%**(knowledge_gap 24.0% + capability_limit 8.8%);环境 9.4%。即失败更多源于"对信息的处理方式错了",而非"模型根本做不到"。
证据:M3,`epistemic_CI [0.549, 0.607]`。配 sudo 案例(`sudo: not found` 被误读为权限问题)。
> 脚注:knowledge_gap 计入能力侧——其 87%(246/284) 被标为 model-layer 失败,缺的是领域/工具知识(ACL 语义、git-lfs 机制、框架约定;查证也需能力理解);"该查未查"式的接地失败已分别归入 false_premise / premature_action(认知侧)。若改计入认知,认知占比升至 82%,本文取保守归类。

**F2 失败锁死集中在绝对早期窗口。** hazard 峰值 0.084 在第 13 步;第 5 步前已锁死 24%、第 10 步前 45%、第 20 步前 69%。按绝对步数算,与轨迹总长无关。
证据:M2 + M1 `cumulative_commit`。

**F3 ★ 失败是两阶段过程,六成留有干预窗口。** 犯错(t_err 中位 7)与锁死(t_commit 中位 12)是两个可区分时刻;60.9% 的轨迹有 ≥1 步的犯错—锁死窗口、43.9% 有 ≥3 步,但 agent 几乎从不利用。
证据:M1,`lag_ge1_CI [0.58, 0.64]`、`lag_ge3_CI [0.41, 0.47]`。三时间点拆分的必要性由 M10 佐证:v1 单点(command_index_ratio.n)与 t_err/t_commit 的 ±2 步一致率仅 **74.7% / 63.9%**(matched 869),说明旧单点混淆了两个概念。

**F4 ★★ 验证纪律,而非探索或运气,是成败的分水岭。** 全文最硬的对照发现。
- pass 宣称前验证 **96.1%** [94.4–97.5] vs fail 锁死前验证 **24.4%** [22.0–26.9];
- 任务内配对零反例:59 个混合任务中 **57 个 pass 验证率更高、0 个相反**,sign p≈1.4×10⁻¹⁷;
- 证伪"探索不足"假设:fail 前 8 步探索反而略多(50.8% vs 44.4%),但效应量小(Cliff's δ=0.11)且未过任务内控制(配对 27/59,p=0.6)——"探索差异"降级为脚注,验证差异才是真分水岭;
- 犯错本身不区分成败:71% 的 pass 也遭遇错误并恢复了 80%,fail 侧 46% 零恢复尝试。
证据:M5 + M7 + M6。

**F5 ★ 失败的实时可检测性是回溯性的:能确认已死,难以预警将死。** oracle 实验对"九成有迹可循"的关键限定。
- 标注者事后看全程,68% 的失败在锁死前有可观察先兆(tierA,**中位提前 6 步**);
- 但实时监视器只看前缀时,**lead_median = 0、lead_mean 仅 0.7–1.9 步**,几乎只在锁死当步或之后才报警(caught_before_commit 仅 3.7%–8.7%);
- 即"事后可见"与"实时可见"之间存在真实鸿沟:先兆是回溯性可辨的,站在当下淹没在正常波动里。
证据:M4(标注侧)对照三份 oracle 的 `lead_time`(实时侧)。

**F6 ★★ 失败可检测性沿"自暴露↔规格相对"分层,瓶颈是任务规格而非监视器的判断尺度。** oracle 实验的机制发现,也是最可操作的工程结论。
- 给监视器注入任务核心要求(**V2 slug → V3 spec**,单变量消融),recall **18%→29%**、F1 30%→41%,且提升是**选择性**的:spec_neglect **3%→22%**(7×)、capability_limit 12%→30%、false_premise 15%→32%,而自暴露类(environment_obstacle) 38%→42% 几乎不动——干净的因果分离(效应只落在规格相对类);
- **对照:光校准判断措辞(V1 保守 → V2 校准,不加规格)只把 recall 从 14% 抬到 18%(+4pp)**,而注入规格再抬 +11pp——规格的边际价值是判断尺度的近 3 倍,坐实"瓶颈是监视器知不知道任务要求,而非敢不敢喊";
- 静默失败检测翻倍:silent recall 14%→28%——静默的"静默"一半是相对于"不知道任务要求的观察者";
- 无难度泄漏:成功轨迹早期前缀(0.2–0.3)误报仍仅 2–3%,误报堆在深层,§4 guard 通过;
- 代价诚实:recall 升、precision 降(88%→72%),是"敢喊"的必然权衡。
证据:三份 oracle results 的 PR、按 trigger 的 recall 表、`fp_by_prefix_fraction`。

**F7(支撑)独立可靠性背书。** 监视器从未见过人工标注,其独立指认的"决定性错误步"86–88% 落在标注 t_commit ±2 步内(86.1/88.0/86.8%)。放 methodology,部分替代一致性研究。
证据:三份 oracle 的 `decisive_vs_tcommit.within2`。

**F8(支撑)早期信号普遍存在但 agent 不察觉。** 241 条失败(20.4%)在锁死**之前**失败信号已肉眼可见,agent 照样锁死;而被标为"无视信号是根因"的只有 49 条——说明无视证据作为伴随行为远比作为根因普遍。
证据:M1 `surface_before_commit=241` 对照 M3 `ignored_signal=49`。

**F20(支撑)主发现对"全员失败任务"不敏感(稳健性)。** 排除 28 个 all-fail 任务后(n=639,纯混合任务),主发现全部挺住:认知主导 **56.3%**(vs 全集 57.9%)、犯错–锁死窗口 lag≥1 **62.4%**(vs 60.9%)、静默 **28.2%**(vs 28.0%)、可观测窗口 tierA **67.1%**(vs 68.2%)、fail 锁死前验证 27.4%。证明 F1/F3/F5 不是被少数"全员失败的难任务"驱动的。放 threats-to-validity。
证据:M8。

## RQ2：失败如何演化（锁死之后发生了什么）

**F9 ★ 锁死是行为的断层线:验证被整体推迟到不可逆点之后。** 逐轨迹配对(每条自己当对照,消除任务混杂):
- 探索 E 43.1%→7.7%(仅 6.3% 的轨迹锁死后探索上升);
- 验证 V 4.5%→29.9%(72.6% 上升);
- 宣称 C 0.1%→16.9%(71.6% 上升);
- 全部 Wilcoxon p≈0。
意义:失败 agent 不是不验证,是验证时序错位——它是收尾仪式,不是事前把关。与 F4 互锁。
证据:M11。

**F10 ★ 失败有五种"死法",误诊修复最贵。** 按 awareness×尾部行为分型:
- 仪式收尾 theatrical_winddown 27.6%(尾 9,占浪费 14.9%,静默 39.8%);
- **误诊修复 misdiagnosed_repair 24.1%(尾 21,占浪费 39.3%)**——以四分之一案例吞近四成浪费,最贵;
- 快速投降 quick_capitulation 18.2%(尾 2,浪费 3.7%,静默 50.5%——最高);
- 造假退场 fabricated_exit 15.1%(尾 8,浪费 13.4%);
- 盲目坚持 blind_persistence 14.9%(尾 17,浪费 28.7%)。
锁死后总浪费 27,424 步。静默失败主要由快速投降(不留痕)和仪式收尾(造假痕)贡献。
证据:M14。

**F11 恢复有"20 步保质期"。** 成功的恢复中位 5 步完成、91% 在 20 步内;失败的恢复尝试中位拖 13 步、p90 达 62 步、最多 122 次尝试。拖过 20 步未成基本是僵尸执行。
证据:M13。

**F12 失败死得很体面,验证流程是空壳。** 宣称完成前 3 步内有验证动作:fail 69.6% vs pass 83.0%——只差 13 个百分点(对比 F4 的 72 点鸿沟)。即失败 agent 形式上几乎和成功者一样"讲流程",但流程检测不到真问题。另:29.1% 的失败从不宣称完成(无声退场)。
证据:M12。

**F13 ★ 造假主要是失败后的退场策略,且越过成败边界。** fabrication 占失败 25.7%,其中 83.9% 起始于锁死当步或之后——是 coping 而非 root cause。同种行为也出现在 6.4% [4.4–8.4] 的成功里(suspicious_pass:proxy 解、硬编码输出),即 benchmark 及格线本身有约 6% 水分。
证据:M6 `fabrication_onset_at_or_after_commit=83.9%`、`suspicious_pass`。(旧 Finding 2 并入此处,获得时序定位。)

**F14 ★ 据此早停可省约三分之一失败算力。** oracle 的 early-stop 反事实:在首次报警处停手,save 27%–39%、cost 1.4%–5.5%、net 25%–34%。
- 反直觉:V3 比 V2 多抓一半失败(recall 18%→29%),省的算力几乎没变(net 33%→34%)——因为 V3 多抓的规格相对类锁死早、尾巴短,省不出额外步数。"检测能力↑≠省钱↑"。
证据:三份 oracle 的 `early_stop`。

**F15(支撑)瓶颈不在反应速度。** 失败信号浮出后,会察觉的 agent 中位仅 1 步就察觉(p75=4)。问题在信号侧(28% 静默)和诊断侧(24% 误诊),不在反应。
证据:M16 `awareness_latency`。

## RQ3：失败变异归谁（model vs scaffold）

**F16 ★ 能不能活由 model×scaffold 配对决定。** 成功率方差分解:model 31% [0.14–0.55] 与 agent 29% [0.04–0.50] 大幅重叠不可区分,**交互项 40% [0.22–0.69] 为最大成分**。"对 scaffold 鲁棒"本身是 model 属性:gemini 换 scaffold 摆动 21.4 点、deepseek 16.5 点,而 kimi 仅 1.9 点、qwen 2.5 点。
证据:M15 decomposition + scaffold_sensitivity。

**F17 ★ 怎么死由 model 主导,不由 scaffold。** 失败尾长 model 44% [0.18–0.53] vs agent 8% [0.02–0.21]——CI 干净分离;预警率 model 49% [0.24–0.64] vs agent 5% [0.00–0.18];造假率、静默率也 model 主导。每个模型有偏好的死法:gpt5 是投降派(快速投降 35.6%,失败最便宜),kimi/devstral 是表演派(仪式收尾 41%/40%),claude 是造假退场最高(20.4%,呼应其 35% 造假率)。
证据:M15 + M14 by_system。步数上限混杂已排除(near-cap 仅 0.2–0.3%)。

**F18 失败"为什么"发生是跨系统普遍的。** model×trigger 与 agent×trigger 的 Cramér's V 仅 0.101 / 0.131(弱关联)——认知主导(F1)是全系统共性,不是某个差模型拖累。给 F1 的普适性盖章。
证据:M16。

**F19(支撑)成功率本身的系统差异。** pass rate:gpt5 最高区间(0.34–0.45)、deepseek 跨度最大(0.27–0.44)、kimi/qwen 低且稳。与 F16 配合说明"单一 scaffold 上的 benchmark 排名不可迁移"。
证据:M15 scaffold_sensitivity。
